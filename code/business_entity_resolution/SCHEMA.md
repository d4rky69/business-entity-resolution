# Business Entity Resolution: Data & File Schema Specification

## 1. Golden Rules of Data Handling

> [!IMPORTANT]
> - **No Source Column in Raw Files:** Raw input files do **not** contain a `source` column. A record's source source is strictly determined by its file and its `entity_id` prefix (`S1-`, `S2-`, or `S3-`).
> - **Explicit Tab Delimiter:** All files in this challenge are tab-separated (`.tsv`). All TSV reads and writes **must** use `sep='\t'` explicitly (e.g. `pd.read_csv(path, sep='\t')` and `df.to_csv(path, sep='\t', index=False)`). Reading without `sep='\t'` silently concatenates entire lines into a single column because addresses and ID lists contain commas.
> - **Country Domain:** The dataset contains **no country other than US, India, and France**. Training data covers `US` and `India`. The test set additionally contains `France` (which does **not** appear in training data). Do not hardcode, filter out, or one-hot encode country to only `{US, India}`. Every test entity, including France, must be processed and present in submissions.

## 2. Raw Input Dataset Schemas

All input datasets are tab-separated (`.tsv`) UTF-8 text files located in `dataset/train/` and `dataset/test/` (or `data/raw/dataset/`).

### Source Records (`*_source1.tsv`, `*_source2.tsv`, `*_source3.tsv`)
Each row represents a noisy fragment of an entity record.

| Column Name | Data Type | Nullable | Description & Constraints | Example |
| :--- | :--- | :--- | :--- | :--- |
| `entity_id` | String | No | Unique identifier for the record. Prefix dictates source (`S1-`, `S2-`, `S3-`). | `S1-00042` |
| `business_name` | String | Yes | Name of business entity (subject to typos, abbreviations, legal suffixes, translations). | `Walmart Supercenter, Inc.` |
| `business_address` | String | Yes | Physical/mailing address (may have missing PIN codes, landmarks, format variations). | `702 SW 8th St, Bentonville, AR 72716` |
| `country` | String | No | Country label: `US` or `India` (train); `US`, `India`, or `France` (test). | `US` |

### Ground Truth (`train_ground_truth.tsv`)
Ground truth matching relationships for the training set.

| Column Name | Data Type | Nullable | Description & Constraints | Example |
| :--- | :--- | :--- | :--- | :--- |
| `source1_entity_id` | String | No | Primary `entity_id` from Source 1 (the reference anchor). | `S1-00001` |
| `matched_entity_ids` | String | Yes | Comma-separated list of matching `entity_id`s from Source 2 and/or 3. Empty string if singleton. | `S2-00047,S3-00812` |

## 3. Internal Working Schemas

These files are stored in `data/interim/` to support modular, staged execution.

### Candidates Long Working Table (`data/interim/candidates_long.tsv`)
Working candidate pairs generated by the multi-pass blocking stage.

| Column Name | Data Type | Description |
| :--- | :--- | :--- |
| `source1_entity_id` | String | Anchor Source 1 ID. |
| `candidate_entity_id` | String | Candidate match ID from Source 2 or Source 3. |
| `block_reason` | String | Pipe-delimited string of blocking rules that triggered this pair (e.g. `postal_match\|name_token_match`). |

### Feature Matrix (`data/interim/features.tsv`)
Pairwise similarity feature table consumed by the training classifier or inference scorer.

| Column Name | Data Type | Description |
| :--- | :--- | :--- |
| `source1_entity_id` | String | Anchor Source 1 ID. |
| `candidate_entity_id` | String | Target candidate ID. |
| `name_exact_match` | Float (0/1) | Binary indicator if cleaned base names match exactly. |
| `name_lev_ratio` | Float [0, 1] | Levenshtein similarity ratio between base names. |
| `name_token_sort_ratio`| Float [0, 1] | Token sort ratio (word order invariant). |
| `name_jaccard` | Float [0, 1] | Word-token Jaccard set overlap. |
| `addr_lev_ratio` | Float [0, 1] | Levenshtein similarity ratio between cleaned addresses. |
| `addr_jaccard` | Float [0, 1] | Word-token Jaccard set overlap on addresses. |
| `postal_match` | Float (-1, 0, 1)| `1.0` if match, `0.0` if mismatch, `-1.0` if either is missing. |
| `country_match` | Float (0/1) | `1.0` if countries match, else `0.0`. |
| `target_source_s2` | Float (0/1) | `1.0` if candidate is from Source 2, `0.0` if Source 3. |

## 4. Official Output / Submission Schemas

Both submission files are tab-separated (`.tsv`) and stored in `output/`.

### 1. `output/matching_results.tsv` (Scored on Leaderboard)
Final predicted entity matches.

| Column Name | Data Type | Description |
| :--- | :--- | :--- |
| `source1_entity_id` | String | Unique Source 1 ID from `test_source1.tsv`. Every test S1 entity must appear exactly once. |
| `matched_entity_ids` | String | Comma-separated list of predicted S2/S3 entity IDs. Empty string for singletons (no matches). |

**Rules:**
- Header must be exactly: `source1_entity_id\tmatched_entity_ids`
- No self-matches: `S1-` IDs are strictly prohibited in `matched_entity_ids`.
- No internal duplicates: e.g. `S2-001,S2-001` is invalid.
- Target IDs must exist in `test_source2.tsv` or `test_source3.tsv`.

### 2. `output/candidate_pairs.tsv` (Audit & Reduction Verification)
The candidate set produced by blocking and fed into the matching model.

| Column Name | Data Type | Description |
| :--- | :--- | :--- |
| `source1_entity_id` | String | Unique Source 1 ID from `test_source1.tsv`. Every test S1 entity must appear exactly once. |
| `candidate_entity_ids` | String | Comma-separated list of candidate S2/S3 entity IDs considered for matching. Empty if no candidates found. |

**Rules:**
- Header must be exactly: `source1_entity_id\tcandidate_entity_ids`
- Must represent the **LAST-stage candidate set** scored by the model (not an early raw blocking dump).
- Every ID in `matching_results.tsv` should be a subset of `candidate_pairs.tsv`.

## 5. Evaluation Metric Specification

The challenge evaluates submissions using **Macro-averaged $F_{0.5}$** across all Source 1 entities:

$$F_{0.5} = \frac{1.25 \times \text{Precision} \times \text{Recall}}{0.25 \times \text{Precision} + \text{Recall}}$$

- **Precision weighting:** Precision is weighted $2\times$ over recall to penalize false positive merges.
- **Singletons:** Source 1 entities with no true matches score:
  - $1.0$ if predicted match list is empty
  - $0.0$ if any match is predicted
- **Macro-average:** The score is computed individually for every Source 1 entity in the evaluation set and arithmetic mean is taken across all entities.
